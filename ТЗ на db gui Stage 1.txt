# 📋 Детальная проработка Этапа 1: Ядро, База данных и Базовый Парсинг

**Цель этапа:** Создать фундамент приложения. Мы не работаем с GUI. Весь код пишется так, чтобы его можно было протестировать через консольные скрипты или юнит-тесты. На выходе этапа мы должны получить инструмент, который берет папку с DOCX-файлами, считает их хэши, извлекает таблицы, очищает текст и складывает результат в CSV и базу данных SQLite.

---

### 📁 1.1. Инициализация проекта и База данных (SQLite)

**Цель:** Настроить структуру проекта и создать базу для хранения информации о файлах.

**Технические детали:**
*   **Структура папок:**
    ```text
    project_root/
    ├── core/               # Бизнес-логика
    │   ├── __init__.py
    │   ├── database.py     # Работа с SQLite
    │   ├── hasher.py       # Хеширование
    │   └── parsers/        # Парсеры
    │       ├── __init__.py
    │       └── docx_parser.py
    ├── data/               # Данные (добавить в .gitignore)
    │   ├── app.db
    │   └── exports/        # Сюда будут складываться CSV
    ├── tests/              # Тесты
    └── main.py             # Временная точка входа для тестов
    ```
*   **Схема БД (таблица `files`):**
    *   `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
    *   `hash` (TEXT NOT NULL) — SHA-256 хэш файла
    *   `path` (TEXT NOT NULL) — Полный путь к файлу
    *   `filename` (TEXT NOT NULL) — Имя файла
    *   `status` (TEXT NOT NULL DEFAULT 'SAVED') — Статус из единого Enum: SAVED (hash, путь, CSV и нормализованные заголовки записаны), PROCESSING (идёт обработка), NEEDS_MAPPING (есть схема без полного маппинга), READY (заголовки сопоставлены, файл можно передавать в Excel), ERROR (текст в error_message). Статусы FOUND и «уже в базе» существуют только в UI и в БД не хранятся.
    *   `error_message` (TEXT) — Текст ошибки (для статуса ERROR)
    *   `is_current` (INTEGER NOT NULL DEFAULT 1) — 1 для текущей версии файла по пути, 0 для старых версий (тот же path, другой hash). История и CSV старых версий сохраняются; в «Подготовить» участвуют только записи с is_current = 1.
    *   `csv_path` (TEXT) — Путь к сгенерированному CSV
    *   `created_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
    *   *Ограничение:* `UNIQUE(hash, path)` — чтобы один и тот же файл по одному и тому же пути не добавлялся дважды. Если по тому же пути появляется файл с другим hash, это новая версия: новая запись получает `is_current = 1`, у старой `is_current` становится 0.

**Ключевые функции (`core/database.py`):**
*   `init_db()` — создание таблиц, если их нет.
*   `add_file(hash, path, filename)` — добавление записи.
*   `get_file_by_hash_and_path(hash, path)` — проверка существования.
*   `update_file_status(hash, path, status, csv_path=None)` — обновление статуса после парсинга.

**Критерии готовности:** Скрипт создает файл `app.db`, в нем есть таблица `files`, функции добавления и чтения работают.

### 🔐 1.2. Модуль хеширования и проверки файлов

**Цель:** Научиться безопасно (без перегрузки памяти) читать файлы и проверять их на дубликаты.

**Технические детали (`core/hasher.py`):**
*   **Алгоритм:** SHA-256. Чтение файла блоками по 8192 байта (чтобы не загружать гигабайтные файлы в память).
*   **Логика проверки (Дубликаты и версии):** Решение принимается по паре `(hash, path)`, а не по одному `hash`:
    1. Вычисляем хэш файла.
    2. Ищем в БД запись с тем же `path` и `is_current = 1`.
    3. *Если путь найден и хэш совпал* — файл уже в базе, ничего не меняем (возвращаем статус `ALREADY_EXISTS`).
    4. *Если путь найден, а хэш другой* — файл изменился, это новая версия: старой записи ставим `is_current = 0`, добавляем новую запись с `is_current = 1` и её хэшем. CSV и история старой версии сохраняются.
    5. *Если путь не найден* (даже если такой `hash` уже есть у файла в другой папке) — добавляем новую запись с `is_current = 1`. Копия файла в другой папке — это отдельная запись, а не новая версия.

**Ключевые функции:**
*   `calculate_sha256(file_path) -> str`
*   `process_file_entry(file_path) -> dict` — возвращает словарь `{"result": "NEW/ALREADY_EXISTS/NEW_VERSION", "hash": "...", "path": "...", "is_current": 1}`.

**Критерии готовности:** Запускаем скрипт на папке. Файлы без дублей добавляются в БД. Если скопировать файл в другую папку и запустить снова — создается вторая запись (дубликат). Если запустить дважды на одной папке — ничего не меняется.

### 📄 1.3. Парсер DOCX (Ядро)

**Цель:** Извлечь таблицы из документов, корректно обработать объединенные ячейки и сохранить в CSV.

**Технические детали (`core/parsers/docx_parser.py`):**
*   **Библиотека:** `docx2python`.
*   **Извлечение:** Метод `docx2python(file_path).body` возвращает вложенные списки: `[Таблица][Строка][Ячейка]`.
*   **Очистка текста (Критически важно):** Внутри ячейки `docx2python` может вернуть список строк (если там несколько абзацев) или строку с переносами `\n`.
    *   *Функция очистки:* Рекурсивно проходит по ячейке, склеивает все куски в одну строку, заменяет `\n`, `\r`, `\t` на пробелы, удаляет лишние пробелы по краям (`strip()`).
*   **Экспорт в CSV:**
    *   Для каждой извлеченной таблицы создается отдельный CSV файл.
    *   *Путь:* `data/exports/{hash}_table_1.csv` (чтобы не было конфликтов имен). Пути всех CSV одного файла собираются и записываются в `files.csv_path` через `;`.
    *   *Кодировка:* `utf-8-sig` (чтобы Excel открывал кириллицу без кракозябр).
*   **Интеграция с БД:** После успешного сохранения CSV в БД записываются пути ко всем CSV файла (через `;` в `csv_path`), а статус файла становится `SAVED`. Заголовки на этом шаге не обрабатываются: их нормализация происходит позже, по кнопке «Подготовить».

**Ключевые функции:**
*   `clean_cell_text(cell) -> str` — очистка текста в ячейке.
*   `extract_tables_from_docx(file_path) -> list` — возвращает список таблиц (список списков).
*   `save_table_to_csv(table_data, output_path)` — сохраняет таблицу в CSV.

**Критерии готовности:** Запускаем на проблемном Word-файле (том, где были объединенные ячейки). Открываем полученный CSV в Excel: все колонки на своих местах, объединенные ячейки заполнены правильным текстом (без сдвигов влево), текст очищен от случайных переносов строк.
