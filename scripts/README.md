# Скрипты проекта

Все команды запускаются из корня проекта. В коде приложения и тестах используется только `process_folder.py`; остальные скрипты автономные, их никто не импортирует (проверено поиском по `from scripts` и по именам файлов). Скрипты `probe_*`, `check_svor_numbers.py` и `dump_table_head.py` только читают данные, ничего не меняют (пишут лишь свой отчёт xlsx). Для вывода кириллицы в файл удобно задать `set PYTHONUTF8=1`.

## Единый вид работы скриптов

Все скрипты ведут себя одинаково (общий код в `report_utils.py`):
1. При запуске печатают, какие папки, файлы или БД приняты в обработку (число файлов) и папку результата. Несуществующие пути помечаются «НЕТ ТАКОГО ОБЪЕКТА, пропуск».
2. По ходу работы печатают счётчик `[группа] N/M (всего K/T) имя`.
3. По окончании печатают итог («Обработано без проблем: N из M»), путь к папке результата и список проблемных файлов с причиной.
4. Пишут отчёт в xlsx. Файлы с ошибкой («ОШИБКА») и файлы без обработки («НЕ ОБРАБОТАН») перечислены в том же xlsx ниже данных, красным, с причиной.
5. Если xlsx открыт в Excel, скрипт пишет «НЕ ЗАПИСАН» и работу не обрывает. Перед повторным запуском закройте файл.

Папка результата у скриптов `probe_*` и `dump_table_head.py` меняется ключом `--out`. Исключение: `check_svor_numbers.py`, `probe_dashes.py`, `probe_style_numbering.py` и `probe_xn_types.py` (см. «Короткие пробы») этого поведения не имеют, они печатают только в консоль.

### report_utils.py
Общий модуль, не запускается сам: `list_documents`, `print_plan`, `Progress`, `write_workbook`, `print_summary`. Используется всеми скриптами, кроме `export_headers.py` (он содержит собственную копию того же вывода, поведение у них одинаковое).

## Рабочий скрипт

### process_folder.py
Сквозной прогон папки: штамп, хэш и версия документа, запись в SQLite (`data/app.db`), CSV таблиц в `data/exports/`. Вызывается также из `main.py`.

    python -m scripts.process_folder ВОР

Запускать как модуль (`-m`), иначе не найдётся пакет `core`.

Что печатает: в stderr план (папка, число файлов, БД, папка результата) и счётчик `[N/M] файл ... результат, CSV: n`; в stdout итог («Файлов», «Обработано: N из M»), пути к CSV и отчётам, список ошибок.
Отчёты в папке CSV этой БД: `_report_<папка>.tsv` (как раньше) и новый `_report_<папка>.xlsx` с теми же столбцами. Ниже данных в xlsx и в консоли перечислены проблемные файлы: «ОШИБКА» (таблицы не извлечены или исключение при разборе) и «ШТАМП НЕ ПОЛНЫЙ» (`stamp_status` не `OK`).
Режимы `--prune` и `--drop-db` не менялись.
Изменение в поведении: при запуске из консоли исключение на одном файле теперь не обрывает прогон, файл попадает в отчёт как «ОШИБКА». Функция `process_folder(...)` без нового параметра `errors` ведёт себя как раньше (исключение пробрасывается).

Используется в коде (единственный скрипт, который импортируется):
- `main.py` (строка 43): `from scripts.process_folder import main`, консольная точка входа.
- `core/search/tasks.py` (строка 35): `CONVERTED_DIR` и `export_tables`. `TaskManager` по умолчанию сохраняет файлы тем же пайплайном «парсер → CSV».
- `tests/test_docx_parser.py` (`test_process_folder_saves_record_and_csv`): вызывает `process_folder`.
- Упоминается в `docs/stage1.md`, `docs/stage3.md` и в `ТЗ на db gui Stage 1.md`. Менять `export_tables` и `CONVERTED_DIR` нужно с оглядкой на `TaskManager` и GUI.

## Выгрузка

### export_headers.py
Экспортирует наборы заголовков главной таблицы в Excel по типам документов: один файл `headers_<папка>.xlsx` на папку, одна строка на уникальный набор (число файлов, профиль, пример файла, заголовки по столбцам).

    python scripts/export_headers.py [--out data/exports/headers] [ВОР КЖ СВОР СО]

По умолчанию обрабатывает ВОР, КЖ, СВОР, СО.

### pq_sync.py

Выгрузка и замена кода запросов Power Query в книге xlsx (имена и связи сохраняются). Формат DataMashup (код, метаданные, права, `connections.xml`) читает и пишет готовый пакет [pyOpenVBA](https://pypi.org/project/pyOpenVBA/) (`pip install pyOpenVBA`, есть в `requirements.txt`), собственного разбора формата в скрипте нет; скрипт только переводит папку `.pq` <-> книга и пишет отчёт. Книга должна быть закрыта в Excel. Нигде в коде не используется. Для запроса, код которого кончается комментарием `//`, скрипт добавляет перевод строки, иначе `;` пакета попадает в комментарий.
- `python scripts/pq_sync.py list "PQ/ВОР/шаблон ВОР.xlsx"` - список запросов.
- `python scripts/pq_sync.py export "<книга>.xlsx" [--out папка]` - по файлу `.pq` на запрос и `_manifest.json`; по умолчанию папка `<книга>_pq/`.
- `python scripts/pq_sync.py new <папка> "<новая книга>.xlsx" [--force]` - создаёт НОВУЮ книгу и записывает в неё все запросы из папки как «только подключения» (без листов и таблиц). Существующий файл без `--force` не перезаписывается. Пример: `python scripts/pq_sync.py new PQ/ВОР/exported "PQ/ВОР/шаблон ВОР_exported.xlsx" --force`. В Excel не открывалось.
- `python scripts/pq_sync.py import <папка> "<книга>.xlsx" [--add] [--prune] [--dry-run]` - загружает правленые `.pq` из папки в книгу (из папки В файл), заменяя код запросов с тем же именем. Книга заменяется на месте, прежняя сохраняется как `<книга>.bak.xlsx`. `--add` добавляет новые запросы (только подключение, без настроек загрузки), `--prune` удаляет запросы без `.pq`, `--dry-run` ничего не пишет.
- Отчёт `_export_report.xlsx` / `_import_report.xlsx` лежит рядом с результатом.

Служебные файлы в папке выгрузки (править их не нужно):
- `_manifest.json` — связь файла `.pq` с именем запроса (нужна, если имя запроса нельзя записать в имени файла). `import` и `new` читают его; без манифеста имя запроса берётся из имени файла (`fnProcessFile.pq` → `fnProcessFile`). Не правьте вручную: новый запрос добавляйте просто файлом `.pq` с нужным именем. Если переименуете `.pq`, имя запроса возьмётся из старой записи манифеста, поэтому лучше не переименовывать. Хранится рядом с `.pq`, показывает, из какой книги сделана выгрузка. Поля `shared` и порядок запросов `import` и `new` не используют (проверено только по чтению `_read_dir`).
- `_export_report.xlsx` — отчёт о выгрузке, скриптом не читается. Можно удалить или не коммитить (при желании добавьте в `.gitignore`). Следующий `export` в ту же папку перезапишет его.

Что важно понимать про `import` (неочевидно):
- Источник — папка с `.pq`, а не другая книга xlsx. Запросы между книгами `import` не переносит. Изменяется только та книга, которую указали вторым аргументом.
- Запросы сопоставляются только по имени: файл `<имя запроса>.pq` заменяет код запроса с таким именем. Если код не изменился, запрос остаётся как был.
- Типичный порядок: `export` (выгрузить в `.pq`) → правка `.pq` в редакторе → `import --dry-run` (посмотреть, что изменится) → `import` без `--dry-run`. Прежняя книга сохранится как `<книга>.bak.xlsx`.
- Без `--add` `.pq`, для которых в книге нет запроса с таким именем, пропускаются. С `--add` они попадают в книгу. В папке могут лежать лишние файлы (например `fxZipExtractAllRobust.pq`), поэтому сначала запускайте `--dry-run`.
- Без `--prune` запросы книги, для которых нет `.pq`, остаются нетронутыми. С `--prune` они удаляются.
- Ключа `--out` у `import` нет: чтобы не менять оригинал, сделайте копию книги и загружайте в неё.

## Книги ВОР, СО, ВОР+СО и сверка итогов

Общее описание процесса: `docs/vor_so.md`. Перед запуском закройте нужные книги в Excel. Скрипты с Excel (`.ps1`) запускают свой скрытый Excel и закрывают его; если у пользователя Excel уже открыт, они отказываются работать (код 2).

### make_reconcile.py (главная команда сверки)
Одна команда: отчёт сверки итогов комплекта в Excel. Её вызывает кнопка «Отчет ВОР+СО» в главном окне (`Controller.reconcile_report` → `core/excel_refresh.py`).

    python -I -X utf8 scripts/make_reconcile.py [папка=data/queries] [метка]

Без метки берётся последний комплект, где есть три книги (`ВОР_`, `СО_`, `ВОР+СО_`). Книги копируются во временную папку, считаются, результат `Сверка_итогов_<метка>.xlsx` кладётся рядом. Книги комплекта должны быть уже обновлены (кнопка «ВОР+СО»). Печатает предупреждения («ВНИМАНИЕ», «НЕТ в…»). Если файл занят Excel, останавливается с сообщением.

### reconcile_totals.py и reconcile_to_xlsx.py
Вызываются из `make_reconcile.py`, можно запускать и отдельно.
- `reconcile_totals.py <папка с c.xlsx v.xlsx s.xlsx> [отчёт.tsv]` — сверка итогов ВОР, СО и сводной. Суммы берутся с листа `Связь_ВОР_СО` по формулам мер, а если листа нет (данные только в модели) — из сводной (заголовок ищется по «Названия строк»). Строки, где объём СО сравнить нельзя, идут отдельно: «остаток объяснённый» (нет аналога, другая единица) и «остаток к проверке» (ВОР без доли: сдвинутая ссылка или объём СО отдан другой строке). В конце раздел «ПОЯСНЕНИЯ».
- `reconcile_to_xlsx.py [отчёт.tsv] [книга.xlsx]` — оформляет TSV в Excel (5 листов, фильтры, закреплённая шапка, пояснения на листе «Итоги»).
- Тестов нет (см. `docs/backlog.md`).

### run_kit_check.py
Прогон одного комплекта из `РД/` по цепочке ВОР → СО → ВОР+СО в Excel, в отдельной рабочей папке `data/_pq_work/<метка>/` (проект не меняется). Стадии по очереди, каждая короче ~3 минут:

    python -X utf8 -m scripts.run_kit_check <подстрока пути в РД/> <метка> build
    python -X utf8 -m scripts.run_kit_check <подстрока> <метка> refresh 1    # 1 — ВОР, 2 — СО, 3 — ВОР+СО
    python -X utf8 -m scripts.run_kit_check <подстрока> <метка> report      # лист «Ошибки»

### make_so_template.py и make_vor_so_template.py
Сборка шаблонов `PQ/СО/шаблон СО.xlsx` (из шаблона ВОР) и `PQ/ВОР+СО/шаблон ВОР+СО.xlsx`. **`make_vor_so_template.py` не запускать на рабочем шаблоне: он стирает модель данных и сводную**, которые пользователь добавил вручную. Правки запросов вносят в `.pq` и загружают в шаблон через `pq_sync.py import`.

### apply_model_measures.ps1
Меры модели книги ВОР+СО: `СуммаСО`, `СуммаВОР`, `СправочноСО`, `СтатусСвязи` (формулы DAX с маской `FORMAT "# ##0.###############"`: в DAX десятичный знак точка).

    powershell -NoProfile -ExecutionPolicy Bypass -File scripts\apply_model_measures.ps1 -Path книга.xlsx -Apply [-Test] [-Save]

`-Apply` задаёт формулы, `-Test` строит временную сводную для проверки, `-Save` сохраняет. Делайте на копии шаблона.

### refresh_books.ps1 и excel_session.ps1
- `refresh_books.ps1 -Books "ВОР.xlsx|СО.xlsx|ВОР+СО.xlsx"` — обновляет книги по очереди в своём Excel, сохраняет и закрывает. Её вызывает кнопка «Сформировать» в режиме ВОР+СО. Код 0 — всё обновлено, 1 — ошибки (книга с ошибкой не сохраняется, дальше не идёт), 2 — Excel пользователя открыт.
- `excel_session.ps1` — общий помощник (`Start-ExcelSession`, `Stop-ExcelSession`), подключается точкой.

## Диагностика (только чтение)

Отчёты по умолчанию лежат в `data/exports/probes/` (`dump_table_head.py` — в `data/exports/dumps/`).

### check_volumes.py и check_volumes_docx.py

Сверка объёмов (колонка «Кол-во») для книги СО. Книга должна быть обновлена в Excel: скрипты читают кэш листов.

```
python -X utf8 scripts/check_volumes.py "data/queries/СО_….xlsx"        # результат запроса ФайлBinary ↔ CSV
python -X utf8 scripts/check_volumes_docx.py "data/queries/СО_….xlsx"   # CSV ↔ таблицы Word
```

Первый сравнивает суммы по файлу и по каждому NПП (свёртка повторов даёт меньше строк, но суммы равны). Второй берёт документ по хэшу из имени CSV (`files.hash`), определяет колонку количества по тексту шапки Word и сверяет сумму каждой таблицы; невыгруженные таблицы и таблицы без колонки количества попадают в отчёт. Отчёты: `data/exports/_report_volumes.tsv`, `data/exports/_report_volumes_docx.tsv`. Если нет кэша конвертации, второй скрипт откроет Word.

### pq_refresh_check.ps1 и pq_eval.ps1 (проверка запросов в настоящем Excel)

Работают через COM со скрытым Excel на **копии** книги (исходная не меняется). Нужен установленный Excel; книга не должна требовать диалогов.

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\pq_refresh_check.ps1 -Workbook "data\queries\СО_….xlsx" -OutDir data\exports\_pq_check
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\pq_eval.ps1 -Workbook "книга.xlsx" -FormulaFile формула.m -OutFile результат.txt
```

- `pq_refresh_check.ps1` обновляет таблицы запросов по одной (итоговая, самая большая, последней; ~100 с для 89 CSV), пишет `_refresh_log.txt` с текстом ошибки каждого запроса, выгружает таблицы в `<имя>.txt` (UTF-16, табуляция, текстовый формат) и сохраняет `refreshed.xlsx` для `check_volumes.py`. Код возврата 1 при ошибках.
- `pq_eval.ps1` вычисляет одну M-формулу из UTF-8 файла со всеми запросами книги и выгружает таблицу. Для текста ошибки оберните шаг в `try` и верните `Message` таблицей: сам сбой даёт только код 0x800A03EC.
- Оба включают `Queries.FastCombine` (игнорировать уровни конфиденциальности): книга после `pq_sync import` имеет пустую привязку разрешений, и без этого запросы падают с «ссылается на другие запросы или этапы…». Перед работой `pq_refresh_check.ps1` пересохраняет копию в Excel, чтобы привязка была настоящей.
- Файлы `.ps1` без кириллицы в тексте: Windows PowerShell 5 читает их как ANSI.

### dump_table_head.py
Первые строки сырых таблиц файлов или папок (`.doc`, `.docx`), без разбора шапки. Отчёт `table_heads.xlsx`: лист на файл (полный текст ячеек) и лист «Итог».

    python scripts/dump_table_head.py [--rows 8] [--out папка] <файл|папка> [...]

Старая форма `dump_table_head.py <файл> 8` тоже работает.

### probe_doc_types.py
Сводка по шапкам для папок разных типов документов: профиль шапки, тип по штампу, число таблиц, частоты наборов заголовков. `.doc` конвертируются через Word. Отчёт `doc_types_<папка>.xlsx`: листы «Сводка» и «Наборы заголовков».

    python scripts/probe_doc_types.py [--out папка] ВОР СО КЖ

### probe_headers.py
Прогоняет `find_best_match` по заголовкам реальных CSV: оценка, метод (exact, fuzzy, abbreviation), нужна ли ручная проверка, предложенное каноническое имя. Справочник берётся из временной БД. Отчёт `headers_match_<папка>.xlsx`.

    python scripts/probe_headers.py [--out папка] <папка_с_CSV>

### probe_db_state.py
Сводка по БД: `user_version`, число файлов, число файлов без `schema_hash`, число схем, распределение файлов по схемам. БД открывается только на чтение. Отчёт `db_state.xlsx` (листы «БД» и «Схемы»).

    python scripts/probe_db_state.py [--out папка] data\app.db [другая.db ...]

### probe_dropped.py
Для всех таблиц файлов или папок: число колонок в документе, профиль, итоговые заголовки, отброшенные колонки (`dropped`) и первые 6 строк. Помогает проверять правило отбрасывания колонок «Проложен». Отчёт `dropped.xlsx`.

    python scripts/probe_dropped.py [--out папка] <файл|папка> [...]

### probe_nohdr.py
Сводка заголовков по всем `.docx` папки (с вложенными): число файлов, таблиц без шапки, частоты заголовков (в консоли 40 самых частых, в xlsx все). Отчёт `nohdr_<папка>.xlsx`.

    python scripts/probe_nohdr.py [--out папка] [папка, по умолчанию ВОР]

### Короткие пробы без отчёта xlsx
Эти четыре скрипта написаны при отладке парсера. Они не используют `report_utils`: просто печатают результат в консоль, ничего не меняют и нигде не импортируются.

- `check_svor_numbers.py` — первая колонка каждой таблицы `.docx` после исправления автонумерации (`numbering_fixed`): первые 14 и последние 4 значения. Показывает, развернулись ли номера (в т.ч. заданные через стиль абзаца).

      python scripts/check_svor_numbers.py <файл.docx>

- `probe_dashes.py` — ячейки с `--` после разбора (артефакт списков `docx2python`). Печатает файлы с примерами и общее число файлов с `--`. Остаток `--` в середине текста (например `ГР--10.02`) `clean_cell_text` не трогает.

      python scripts/probe_dashes.py <папка> [макс. файлов с примерами, по умолчанию 5]

- `probe_style_numbering.py` — нумерация через стили: стили `styles.xml` с `numPr`, частоты `pStyle` в документе и сырой XML строк 3–5 первой таблицы. Для выяснения, откуда берётся номер, если в абзаце нет своего `numPr`.

      python scripts/probe_style_numbering.py <файл.docx>

- `probe_xn_types.py` — тип документа по штампу для `.docx` папок (с вложенными): частоты типов; для `XN` и пустого типа печатает файл, шифр и «Наименование документа». Проверка правила «XN + Кабельный журнал → КЖ» (`doc_type_from_name`).

      python scripts/probe_xn_types.py <папка> [...]

### probe_paren.py
Ищет в таблицах `.docx` строки, где номер записан со скобкой (`18)`), и показывает, есть ли у такой таблицы шапка. Отчёт `paren_<папка>.xlsx`.

    python scripts/probe_paren.py [--out папка] [папка, по умолчанию ВОР]
