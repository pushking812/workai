# ASK.md — заметки проекта workai

## Правила работы
- Инструменты есть в каждом запросе. Писать «инструментов нет» нельзя: вызывай нужный.
- Команды идут в PowerShell: `;` вместо `&&`, `Get-ChildItem -Recurse -Name` вместо `dir /s /b`.
- Файлы читай по одному и частями по 120–150 строк, пока не дойдёшь до конца. Обрезанный результат — не конец файла: перечитай недостающие строки.
- Код и содержимое файлов в чат не выводи. Правки записывай в файл, в чат пиши одну-две строки: что изменено и где.
- Тесты запускай сам (`python -m pytest -q`), пользователя не проси. В чат — итог и строки с ошибкой.
- Если вызов не удался, исправь команду и повтори. Вопрос пользователю — только если без ответа нельзя продолжить.
- В этот файл пиши только решения и статус (до 10 строк на тему), не пересказ прочитанных файлов. Ограничение: файл целиком не больше 12 000 знаков, иначе сайт обрежет хвост.

## Как писать в чат
- Перед группой вызовов — 1–2 строки: что делаю и зачем, с именами файлов.
- После группы вызовов — 1–2 строки: что получилось (файл, число строк, результат теста).
- В конце каждой задачи — строка «Итог: успешно» или «Итог: не удалось — причина».
- Содержимое файлов и код в чат не выводить, только в файл.

## Power Query (PQ)
- Папка `PQ` содержит выгрузки запросов из `test.xlsx`. Это прообраз файлов Power Query, которые будет выгружать приложение.
- Остальные правила (роль `test.pq` и `fx*.pq`, три рабочие папки) утеряны, их нужно продиктовать заново.

## Проект
- Приложение для структурирования БД строительных документов (ВОР): Python backend, SQLite, GUI на PyWebView + HTML/CSS/JS (мост `pywebview.api`).
- ТЗ лежат в `ТЗ на db gui common.md` и `ТЗ на db gui Stage N.md` (6 этапов). Читай нужный этап из файла, не из этих заметок.
- Этапы: 1 БД, хэши, парсер DOCX (docx2python), CSV; 2 заголовки, схемы, синонимы, fuzzy-маппинг (rapidfuzz, порог 85); 3 поиск файлов, потоки; 4 каркас GUI; 5 настройки и маппинг; 6 экспорт в Excel (Power Query), PyInstaller.
- Этап 1: таблица `files` (UNIQUE(hash, path)), SHA-256 блоками по 8192, версия определяется штампом (doc_code + revision + revision_date), результаты `NEW` / `ALREADY_EXISTS` / `NEW_VERSION` / `NEW_VARIANT`, CSV в `utf-8-sig` (`data/exports/{hash}_table_N.csv`).
- Исходные ВОР лежат в папке `ВОР`. Образцы: `16_ЕСТ-ПМ-80825-Р-1-ЭС1_ВОР.docx` (ЭС1), `ЕСТ-ПМ-80825-Р-1-ИСВН_ВОР.docx` (ИСВН).
