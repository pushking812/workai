# Помещения: экспликации, справочник, AI

Состояние на 2026-11-15. Разделы: сводный Excel из PDF, справочник в БД и окно «Помещения…», обмен через xlsx, AI-проверка.

## 1. Сводный Excel из PDF-экспликаций

- Вход: PDF в `ДопФайлы\Помещения` (подпапка `Тип экспликаций 1`). Рядом могут лежать ручные `*.pdf.csv`: они нужны только для сверки.
- Запуск: `python -m scripts.rooms_to_excel` (из venv). Ключ `--ocr_with_ai` отправляет в модель только файлы без текстового слоя.
- Модули: `core/rooms_pdf.py` (разбор экспликаций типов 1 и 2; текстовый слой, для сканов RapidOCR, пометка «OCR»), `core/rooms_ai.py` (промпт и ответ модели), `scripts/win_ocr.ps1` (вспомогательный OCR).
- Результат: `data/exports/Помещения.xlsx`, листы «Помещения», «Проверка», «Файлы», «Сверка_CSV», «Сверка_AI». 19 PDF, 570 записей.
- Источник записи: текстовый слой (13 файлов, 425 записей); для 6 векторных PDF ответ модели с меткой «AI (проверено)» (пользователь проверил 62 спорных помещения, везде прав AI). Ручные CSV остаются эталоном для сверки.
- Известная проблема: `Сенная площадь. 4 подземный этаж.pdf`, итоги не сошлись (замечание на листе «Проверка»).
- Кэш OCR и ответов модели: `data/_pq_work/rooms_cache` (около 3 мин на файл при первом OCR).
- `scripts/ai_check_list.py` собирает список спорных помещений для проверки (`data/exports/Помещения_AI_проверить.xlsx`).

## 2. Справочник в БД

- Модуль `core/reference_store.py`, таблицы `ref_buildings`, `ref_floors`, `ref_rooms` в `data/app.db` (создаются при первом обращении, схема v8 не менялась). Путь к БД абсолютный от корня проекта (`core/database.py`), поэтому не зависит от папки запуска.
- Первое наполнение один раз из `spravochniki.xlsx` (флаг `ref_meta.seeded`). Дальше источник истины БД; файл не читается и не обновляется сам.
- Поля:
  - здание: код (короткое название, до 5 символов), полное название; `name` (краткое) в БД остаётся, окно его не меняет;
  - этаж: код, название, наземный/подземный;
  - помещение: код, название, площадь `area` (м², только чтение в окне), наземный/подземный (пусто = как у этажа).
- Идентификатор `uid`: `BLD-000001`, `FLR-000001`, `ROM-000001`. Создаётся триггером при любой вставке, не меняется при смене кода, не переиспользуется, прямая правка отклоняется. Для ссылок из других таблиц (будущая `КЖ_Трассы_Атрибуты`) предлагается хранить `uid`.
- Правила: удаление используемого значения запрещено (сообщение с причиной, например «Трассы: 1»); смена кода обновляет все места использования; дубли кодов запрещены без учёта регистра и пробелов. Места использования регистрируются через `register_usage(Usage(...))`; пока не зарегистрировано ничего (таблиц КЖ/СО с кодами помещений нет).
- Для остального кода: `reference_store.to_reference(conn)` возвращает `core.reference.Reference`.
- Наземный/подземный: ЗДЦ и ЭП подземные, ДС1 наземный, сырой текст этажа в примечании.

## 3. Окно «Помещения…» (настройки)

- Вёрстка: `ui/index.html` (`ref-popup`), стили `ui/css/style.css`, логика `ui/js/app.js` (функции `*Ref*`), API `get_reference`, `edit_reference` (`api/webview_api.py`, `api/controller.py`).
- Три списка: здания, этажи, помещения. В строке списка только «код - название». Над каждым списком поле фильтра (подстрока без учёта регистра; выбранная запись остаётся видимой).
- Здание: код (5 символов) и полное название в одной строке. Этаж: код и название в одной строке, список наземный/подземный ниже на всю ширину. Помещение: код, площадь (только чтение) и список наземный/подземный в одной строке, название ниже.
- Кнопки «Выгрузить в xlsx…» и «Загрузить из xlsx…».
- Окно в приложении вручную не проверялось (только тесты и `node --check`).

## 4. Обмен через xlsx

- Модуль `core/reference_exchange.py`.
- Выгрузка: листы «Здания», «Этажи», «Помещения» со столбцами как в `spravochniki.xlsx`, связи по кодам, последняя колонка `ID` (uid, при загрузке не читается).
- Загрузка: добавляет недостающее, обновляет названия, признак и площадь. Не удаляет и не переименовывает коды.
- Перенос экспликаций: `scripts/merge_rooms_into_reference.py` (из `Помещения.xlsx` в `spravochniki.xlsx` и БД). Заполняет только пустые названия; прочерк «-», «–», «—» считается пустым. Код `ЗДЦ` из экспликаций = `ЕДЦ` в БД (`BUILDING_ALIASES`). Этажи станций называются `ПС<N>` по «N подземный этаж»; повтор номера помещения на этаже получает код вида `350а (#2)`.
- Выполнено: +8 этажей, +407 помещений, 163 площади; у ЕДЦ 160 названий. В БД 11 зданий, 35 этажей, 616 помещений.
- Не перезаписаны названия трёх помещений ЕДЦ (`ЭТ -1.16.1…3`): они вида «выс. отм. -8.350».
- Код здания ЕДЦ в `spravochniki.xlsx` (`ЗДЦ`) расходится с БД (`ЕДЦ`).
- Способы прокладки (`spravochniki.xlsx`, лист «Способы_прокладки», 22 строки) в БД не переносятся. Исправлено `G20` → `MR20` (строка «Мет. рукав 20»).

## 5. AI (Ask API)

- Клиент `core/ai_client.py`. Ключ: переменная `ASK_API_KEY`, иначе `ai_api_key` в `data/config.json` (`data/` в `.gitignore`). Настройки `use_ai`, `ai_api_key`, `ai_model`; окно получает `config.public_view` (ключ скрыт). Чекбокс «Использовать AI» остаётся, потому что данные уходят на внешний сервер.
- Для PDF: `kind: "pdf"`, `application/pdf`. Подробности в `docs/Ask API docs.txt`.
- Правило: в модель идут только точечные случаи после сужения алгоритмом; исключение — файлы без текстового слоя целиком.
