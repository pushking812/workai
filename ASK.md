# ASK.md — заметки проекта workai

## Правила работы
- Инструменты есть в каждом запросе. Писать «инструментов нет» нельзя: вызывай нужный.
- Команды идут в PowerShell: `;` вместо `&&`. Shell у run_command — cmd, PowerShell-вызовы оборачивай в `powershell -NoProfile -Command`.
- Файлы читай частями по 120–150 строк, не целиком. Сначала поиск по строке, потом ≤60 строк вокруг. Обрезанный результат — не конец файла.
- Вывод pytest и скриптов фильтруй до итога и первых ошибок. Исходные docx и CSV не открывай целиком: числа считай скриптом, смотри 5–10 строк.
- Код и содержимое файлов в чат не выводи. В чат — 1–2 строки: что изменено и где.
- Тесты запускай сам (`python -m pytest -q`, из venv `%TEMP%\workai_venv`), пользователя не проси.
- Если вызов не удался, исправь команду и повтори. Вопрос пользователю — только если без ответа нельзя продолжить.
- Прогоны по умолчанию только на проблемных файлах (находить скриптом). Полные прогоны — только по согласованию с пользователем, заранее назвать число файлов.
- Проверки в Excel: `scripts/pq_refresh_check.ps1` и `scripts/pq_eval.ps1` сами запускают и закрывают свой Excel (`scripts/excel_session.ps1`). Если у пользователя Excel уже открыт — не трогать, спросить.
- Ответы короткие, без таблиц и списков коммитов, если не просили. В конце задачи: «Итог: успешно» или «Итог: не удалось — причина».
- В этот файл пиши только решения и статус (до 10 строк на тему). Файл целиком не больше 12 000 знаков, иначе сайт обрежет хвост.

## Проект
- Приложение для структурирования БД строительных документов (ВОР, СО, СВОР, КЖ): Python, SQLite (`data/app.db`, схема v8), GUI на PyWebView + HTML/CSS/JS (мост `pywebview.api`).
- ТЗ: `ТЗ на db gui common.md`, `ТЗ на db gui Stage N.md` (6 этапов). Читай нужный этап из файла.
- Этапы: 1 БД, хэши, парсер DOCX, CSV; 2 заголовки, схемы, синонимы, fuzzy-маппинг; 3 поиск файлов, потоки; 4 каркас GUI; 5 настройки и маппинг; 6 экспорт в Excel, PyInstaller. Этапы 1, 3, 4 и раздел 6.5 (Power Query) в основном сделаны.
- Эталонные docx лежат в `РД/`. CSV: `data/exports/app/{hash}_table_N.csv`. Временные пробы в корне удаляй.
- Не сделано: `generate_mapping_report`, `core/transformer/data_applier.py` (`apply_mapping`), канонический порядок колонок КЖ, сквозной тест, прогон 22 файлов КЖ, шаблоны КЖ и СВОР, этапы 5–6.

## Power Query
- Шаблоны: `PQ/ВОР/шаблон ВОР.xlsx`, `PQ/СО/шаблон СО.xlsx`, `PQ/Общая/шаблон ВОР+СО.xlsx` (все `.xlsx` в `.gitignore`). Запросы `.pq` лежат рядом (`PQ/*/запросы/`).
- Сборка: СО — `scripts/make_so_template.py`, общая — `scripts/make_combined_template.py` (запускать из venv, `set PYTHONUTF8=1`). ВОР правится через `scripts/pq_sync.py import/export` (пакет pyOpenVBA, правит только `customXml/item1.xml`). Книги правятся как zip, не через openpyxl. Заметки: `.ask-memory/pq_workflow.md`.
- Excel 2016: нет `Text.Middle`, `Text.BeforeDelimiter`, `Text.BetweenDelimiters`, `Text.Start`, `Csv.Document` с `QuoteStyle`, `Table.Schema`, 5-арг. `Table.AddIndexColumn`. Допустимы `Text.Split`, `Text.Range`, `Text.PositionOf`, `List.*`, `Table.Group`, `Table.UnpivotOtherColumns`.
- Кнопка «Сформировать запросы» (`core/query_builder.py`, `Controller.build_queries(mode)`): окно выбора «По типам документов» (книга на тип, `TEMPLATES`) или «ВОР+СО» (одна книга `ВОР+СО_<время>.xlsx`, списки `СписокВОР` и `СписокСО`; нужны оба типа, остальные пропускаются). Нераспознанные шапки СО в общей книге только в отчёте.
- Общая книга: четыре таблицы `Пересечение`, `Только_в_СО`, `Только_в_ВОР`, `Связь_ВОР_СО` (один пункт ВОР → все строки СО из его `NППРДСО`, точное совпадение). Ключ `Шифр|НомИзм|Дата|NПП`. Объёмы не сравниваем (решение пользователя). Открыт вопрос: не слишком ли жёстко дата в ключе (326 случаев «версия СО другая»).
- ВОР: составные значения — итог в `КолВо`, остальные в `ДопКолВО` через ` | `; `32х8` → `КолВо` произведение, `ДопКолВО` первый множитель + «шт.»; многоуровневые разделы через ` | `; `Проверка` для пометок.
- СО: `- // -` = значение выше; дубли по `NПП`; комплекты «в составе:» (в учёт только строка комплекта, пустое `КолВо` = 1 компл.); раздел строго по `N.1`.

## Штамп и разбор документов
- `core/parsers/stamp_parser.py`: `STAMP_CELLS`, `SHIFT`, `read_table_rows` (gridSpan/vMerge), `find_change_label_row`, `parse_stamp` берёт таблицу с максимумом непустых значений. Профили штампа: full (ИСВН), short (ЭС1), unknown (`detect_stamp_profile`).
- Номер и дата изменения — из верхней заполненной графы «Изм.» (`_revision_value`: «Нов.»/«Зам.» → 0). Расхождения штамп/имя файла парсер не правит, а пишет в `discrepancies`.
- Тесты штампа на реальных документах из `РД/` (`_require` ищет по имени): не удалять, а чинить пути. `vor_parsing_results.xlsx` должен быть закрыт в Excel.
- Типы: `core/doc_types.py` (`С`→`СО`, `XN` + «Кабельный журнал» → `КЖ`). СВОР — отдельный тип, шифр в колонках режет `parse_table` (`stage_codes`). `.doc` → `.docx` через `convert_doc.py` (Word COM).
- Шапки: `core/parsers/header_profiles.py` (`parse_table`, профили `cable_basic/section/pipes`, `generic`). Блок «Проложен» не выгружается. Правило усечения: имя уровня >15 символов → слова с 3-го до 3 символов. Пустой столбец без названия отбрасывается.
- Лишних колонок нет: каждая колонка сопоставляется с канонической или добавляется в справочник. `Extra_Column` не нужен.
- Автонумерация docx (`docx_fix_numbering.py`): стиль абзаца, прямой numPr важнее, numId=0 отключает. Артефакт `--` режет `LIST_MARKER_RE`.
- «Сохранить» пропускает файлы с CSV на диске (`TaskManager._already_saved`); изменённый файл — новая запись (другой хэш).
- Этап 3 (бэкенд): `core/search/`, `api/controller.py`, описание в `docs/stage3.md`. Этап 1: `docs/stage1.md`.
