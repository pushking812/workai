# 📋 Детальная проработка Этапа 2: Справочник колонок и Маппинг (Data Transformation)

**Цель этапа:** Научиться распознавать структуру таблиц. Понять, какие колонки в документе соответствуют «золотому стандарту» (каноническим именам), сгруппировать файлы с одинаковыми ошибками и подготовить данные для интерактивного окна сопоставления (которое появится на Этапе 5).

На этом этапе мы работаем только с кодом (Python + SQLite), без графического интерфейса. Мы создадим «мозг», который будет анализировать заголовки.

---

### 📊 2.1. Нормализация заголовков и «Отпечаток» схемы (Schema Hash)

**Цель:** Привести заголовки из Word к единому виду и научиться группировать файлы с абсолютно одинаковыми наборами колонок, чтобы не заставлять пользователя сопоставлять одно и то же 20 раз.

**Технические детали (`core/transformer/schema_analyzer.py`):**
1.  **Извлечение заголовков:** Берем первую непустую строку из извлеченной таблицы (обычно это `table[0]`).
2.  **Нормализация:**
    *   Приведение к нижнему регистру.
    *   Удаление переносов строк (`\n`), табуляций и лишних пробелов.
    *   Замена буквы `ё` на `е`.
    *   Удаление знаков препинания (точек, запятых), чтобы `"Ед. изм."` и `"Ед изм"` стали одинаковыми.
    *   *Пример:* `"№ п/п"` -> `"n п/п"` -> `"nпп"`.
3.  **Создание «Отпечатка» (Schema Hash):**
    *   Берем список нормализованных заголовков, склеиваем их через разделитель (например, `|`).
    *   Считаем MD5-хэш от этой строки. Это и есть уникальный идентификатор структуры таблицы.
4.  **Сохранение в БД:**
    *   В таблице `files` добавляется колонка `schema_hash`.
    *   Создается новая таблица `schemas`:
        *   `schema_hash` (TEXT PRIMARY KEY)
        *   `raw_headers_json` (TEXT) — исходный список заголовков `["№ п/п", "Наименование", ...]`
        *   `normalized_headers_json` (TEXT) — очищенный список
        *   `mapping_json` (TEXT) — итоговое сопоставление (заполняется позже)

**Ключевые функции:**
*   `normalize_header(text: str) -> str`
*   `generate_schema_hash(normalized_headers: list) -> str`
*   `analyze_and_save_schema(headers: list, file_hash: str)`

### 📚 2.2. Справочник канонических имен и синонимов

**Цель:** Создать базу знаний, которая помнит, что `"Описание работ"`, `"Наименование"` и `"Вид работ"` — это всё один и тот же столбец `"НаименованиеРабот"`.

**Технические детали (`core/database.py`):**
1.  **Таблица `header_synonyms`:**
    *   `id` (PK)
    *   `canonical_name` (TEXT) — Например, `"ЕдИзм"`
    *   `synonym_normalized` (TEXT UNIQUE) — Например, `"единица"` или `"едизм"`
    *   `confidence_score` (REAL) — Уверенность (1.0 для ручного ввода, 0.9 для авто-подбора)
2.  **Первичное заполнение (Seeding):**
    *   При первом запуске (или через отдельный скрипт) таблица заполняется базовыми значениями:
        *   `NПП` <- `"nпп"`, `"n п/п"`, `"номер"`, `"n"`
        *   `НаименованиеРабот` <- `"наименование работ"`, `"наименование"`, `"описание"`
        *   `ЕдИзм` <- `"ед изм"`, `"единица измерения"`, `"ед"`, `"единица"`
        *   `КолВо` <- `"кол во"`, `"количество"`, `"объем"`, `"обьем"`
        *   `СсылкаНаЧерСпе` <- `"ссылка"`, `"ссылка на чертежи"`, `"примечание"`
        *   и т.д.

**Ключевые функции:**
*   `seed_dictionary()` — заполнение базы стандартными значениями при инициализации.
*   `get_canonical_for_synonym(normalized_header: str) -> str | None` — быстрый поиск: если заголовок уже есть в базе, сразу возвращает каноническое имя.

### 🧠 2.3. Нечеткое сопоставление (Fuzzy Matching)

**Цель:** Если точного совпадения в справочнике нет, алгоритм должен «догадаться», что `"Наименование работы"` — это на самом деле `"НаименованиеРабот"`, и предложить это пользователю.

**Технические детали (`core/transformer/fuzzy_matcher.py`):**
*   **Библиотека:** **`rapidfuzz`** (в разы быстрее стандартного `difflib`).
*   **Алгоритм:**
    1.  Берем нормализованный заголовок из Word (например, `"наименование работы"`).
    2.  Сравниваем его со **всеми** каноническими именами и их синонимами из базы.
    3.  Используем алгоритм `token_sort_ratio` (он игнорирует порядок слов).
    4.  Если лучший результат больше порога (например, 85%), мы считаем это совпадением.
*   **Формирование отчета для UI (JSON):**
    *   Для каждой колонки формируется словарь:
        ```json
        {
          "source_header": "Наименование работы",
          "suggested_canonical": "НаименованиеРабот",
          "score": 95.5,
          "is_exact_match": false,
          "requires_manual_review": false
        }
        ```
    *   Если для колонки нет совпадения с высоким рейтингом, ставится флаг `requires_manual_review: true`. Это сигнал для UI (Этап 5), что нужно подсветить поле красным.

**Ключевые функции:**
*   `find_best_match(normalized_header: str) -> dict` — возвращает лучший вариант и рейтинг.
*   `generate_mapping_report(schema_hash: str) -> list[dict]` — собирает отчет по всей схеме.

### 🛠 2.4. Движок применения маппинга (Application Engine)

**Цель:** Функция, которая берет «грязную» таблицу и отчет о маппинге, и выдает чистую таблицу с нужными колонками.

**Технические детали (`core/transformer/data_applier.py`):**
*   **Входные данные:**
    *   `table_data` (сырые данные из `docx2python`, список списков).
    *   `mapping` (словарь вида `{"Наименование работы": "НаименованиеРабот", "Объем": "КолВо", ...}`).
*   **Логика:**
    1.  Проходим по строкам с данными (пропускаем заголовки, начинаем с `table[1:]`).
    2.  Для каждой строки создаем новый словарь (Record).
    3.  Бежим по `mapping`. Если колонка есть в строке — берем значение.
    4.  **Обработка отсутствующих колонок:** Если в Word не было колонки `СсылкаНаЧерСпе`, но она есть в каноне, мы **добавляем** её в запись со значением `None` (или пустой строкой).
    5.  **Игнорирование лишних колонок:** Если в Word есть колонка `Примечание`, которой нет в каноне, мы можем либо отбросить её, либо добавить в конец таблицы как `Extra_Column`.
    6.  Конвертация результата в `pandas.DataFrame` (или список словарей) для сохранения в CSV.

**Ключевые функции:**
*   `apply_mapping(table_data: list, mapping: dict) -> list[dict]` — возвращает структурированные данные.
