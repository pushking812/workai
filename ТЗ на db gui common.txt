Отлично. Подготовка качественного ТЗ — это 50% успеха проекта. Разбиение на этапы позволит нам двигаться итеративно, не уходя в «кроличью нору» и имея на каждом шаге рабочий прототип (MVP).

Ниже представлен **черновой план ТЗ**, разбитый на логические этапы. В каждом этапе указана цель, ключевой функционал и примерный пул задач, которые впоследствии можно будет оформить в коммиты.

# 📋 Черновое ТЗ: Приложение для структурирования БД строительных документов

## 🎯 Общая архитектура
*   **Backend:** Python (логика парсинга, БД, файловая система).
*   **Database:** SQLite (хранение метаданных, хешей, справочников колонок).
*   **Frontend (GUI):** PyWebView (нативное окно) + HTML/CSS/JS (интерфейс).
*   **Связь:** Мост `pywebview.api` (вызов Python-функций из JS и возврат JSON-ответов).

---

## 📦 Этап 1 (смотри детали ТЗ на db gui Stage 1.txt): Ядро, База данных и Базовый Парсинг (Backend Core)
**Цель:** Научиться извлекать таблицы из DOCX, чистить их и сохранять в CSV, а также настроить базу данных для хранения информации о файлах.

*   **1.1. Инициализация проекта и БД:**
    *   Создание структуры папок (core, api, ui, data).
    *   Проектирование схемы SQLite: таблица `files` (hash, path, filename, status, created_at).
    *   Реализация функций CRUD для `files` (добавление, проверка существования по хешу/пути).
*   **1.2. Модуль хеширования и проверки файлов:**
    *   Функция вычисления SHA-256 (`hashlib`).
    *   Логика проверки: если хеш есть, но путь другой — добавляем; если путь тот же — игнорируем.
*   **1.3. Базовый парсер DOCX (на базе `docx2python`):**
    *   Извлечение всех таблиц из документа.
    *   Обработка объединенных ячеек (согласно логике `docx2python`).
    *   Очистка текста от переносов строк и лишних пробелов.
    *   Сохранение извлеченных таблиц в CSV (UTF-8 BOM).
    *   *Коммиты:* `init_db`, `add_hashing`, `create_docx_parser`, `export_to_csv`.

## 🧠 Этап 2(смотри детали ТЗ на db gui Stage 2.txt): Справочник колонок и Маппинг (Data Transformation)
**Цель:** Реализовать логику анализа заголовков, группировки файлов по схемам и подготовку данных для будущего интерактивного сопоставления.

*   **2.1. Извлечение и группировка заголовков:**
    *   Функция, которая берет первую строку таблицы из DOCX и нормализует заголовки (нижний регистр, удаление пробелов).
    *   Создание «отпечатка» схемы (хэширование списка заголовков).
*   **2.2. Справочник синонимов (Сanonical Dictionary):**
    *   Таблица в БД `header_synonyms` (id, canonical_name, synonym).
    *   Заполнение базовыми значениями (НаименованиеРабот -> "Наименование работ", "Описание" и т.д.).
*   **2.3. Алгоритм нечеткого сопоставления (Fuzzy Matching):**
    *   Использование `difflib` или `rapidfuzz` для автоматического подбора пар (например, "Ед. изм." автоматически маппится в "ЕдИзм" с коэффициентом схожести 90%).
    *   Формирование JSON-отчета для фронтенда: какие колонки распознаны, какие требуют ручного вмешательства.
    *   *Коммиты:* `extract_headers`, `init_synonyms_db`, `add_fuzzy_match`, `generate_mapping_json`.

## 🔍 Этап 3(смотри детали ТЗ на db gui Stage 3.txt): Поиск файлов и Управление статусами (Backend Logic)
**Цель:** Реализовать фоновый поиск файлов по директориям и управление процессом.

*   **3.1. Рекурсивный поиск:**
    *   Функция поиска `.docx` файлов по списку директорий и маске (например, `*ВОР*`).
    *   Возврат списка найденных путей.
*   **3.2. Многопоточность и остановка (Threading):**
    *   Запуск поиска и парсинга в отдельном потоке (`threading.Thread`).
    *   Использование `threading.Event` для реализации кнопки «Остановить поиск».
*   **3.3. Управление статусами:**
    *   Логика обновления статуса файла в БД (Найден, В БД, Обработан, Ошибка).
    *   Подготовка API-методов для получения списка файлов с их текущими статусами для GUI.
    *   *Коммиты:* `add_recursive_search`, `implement_threading_stop`, `status_management_api`.

## 🖥 Этап 4 (смотри детали ТЗ на db gui Stage 4.txt): Каркас GUI и Главное окно (Frontend Base)
**Цель:** Запустить нативное окно приложения, отрисовать главный экран и связать его с бэкендом через PyWebView.

*   **4.1. Инициализация PyWebView:**
    *   Создание `main.py`, запускающего окно с локальным HTML-файлом.
    *   Настройка моста для вызова Python-функций из JS.
*   **4.2. Верстка главного окна (HTML/CSS/JS):**
    *   Шапка с кнопками («Настройки», «Поиск», «Стоп», «Сохранить», «Добавить»).
    *   Таблица (DataGrid) для списка файлов: чекбоксы, имя, путь, статус, размер.
    *   Кнопки массового выделения.
*   **4.3. Связывание (API Integration):**
    *   Обработка нажатия «Поиск»: вызов Python-функции, получение списка файлов, обновление таблицы в JS.
    *   Обновление прогресс-бара при фоновом поиске.
    *   *Коммиты:* `init_pywebview`, `create_main_ui`, `connect_ui_to_search_api`.

## ⚙️ Этап 5 (смотри детали ТЗ на db gui Stage 5.txt): Интерактивные окна (Модальные окна GUI)
**Цель:** Реализовать интерфейс для настроек и самого сложного — окна сопоставления колонок (Mapping).

*   **5.1. Окно настроек (Settings Modal):**
    *   Форма: префикс, список директорий, фоновый режим, настройки экспорта.
    *   Сохранение настроек в `config.json` или БД.
*   **5.2. Окно выбора файлов (File Dialog):**
    *   Вызов системного диалога выбора файлов через Python (`tkinter.filedialog` или `pywebview`).
*   **5.3. Окно сопоставления колонок (Mapping Modal) — Ключевая фича:**
    *   Левая панель: список уникальных схем (сгруппированных).
    *   Правая панель: Drag-and-Drop список (SortableJS) для изменения порядка колонок.
    *   Выпадающие списки (Select) для выбора канонического названия.
    *   Кнопка «Применить ко всем файлам с такой схемой».
    *   *Коммиты:* `create_settings_modal`, `add_file_dialog_api`, `create_mapping_ui`, `save_mapping_rules_api`.

## 📤 Этап 6 (смотри детали ТЗ на db gui Stage 6.txt): Экспорт в Excel и Финализация (Export & Polish)
**Цель:** Сформировать итоговый Excel-файл с настроенными запросами Power Query на основе выбранных и обработанных файлов.

*   **6.1. Подготовка шаблона Excel:**
    *   Создание эталонного `.xlsx` файла с настроенными запросами PQ (которые мы писали ранее).
    *   Параметризация путей к CSV.
*   **6.2. Логика экспорта:**
    *   Python берет выбранные файлы, копирует шаблон, подставляет пути к сгенерированным CSV.
    *   (Опционально) Автоматическое обновление данных в Excel через `win32com` (если установлен Excel).
*   **6.3. Обработка ошибок и финальный тест:**
    *   Вывод уведомлений в GUI (например, "Файл X не удалось обработать", "Готово: 15 файлов").
    *   Сборка проекта в `.exe` (через `PyInstaller`).
    *   *Коммиты:* `create_excel_template`, `implement_excel_export`, `add_error_notifications`, `build_exe`.
