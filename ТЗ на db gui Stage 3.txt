# 📋 Детальная проработка Этапа 3: Поиск файлов и Управление статусами (Backend Logic)

**Цель этапа:** Научить приложение находить нужные файлы на диске, делать это в фоне (чтобы интерфейс не зависал) и безопасно останавливать процесс по команде пользователя. Мы также создадим систему статусов, чтобы интерфейс всегда знал, что происходит с каждым файлом (найден, в очереди, обработан, ошибка).

На этом этапе мы готовим «двигатель» для кнопок «Поиск», «Остановить поиск» и «Сохранить».

---

### 📂 3.1. Рекурсивный поиск файлов

**Цель:** Обойти указанные директории и собрать все `.docx` файлы, соответствующие маске (например, `*ВОР*`).

**Технические детали (`core/search/scanner.py`):**
*   **Библиотека:** `os` и `fnmatch` (для работы с масками `*ВОР*`, `*.docx`).
*   **Логика:**
    1.  Принимает список директорий (`list[str]`) и строку маски (например, `*ВОР*`).
    2.  Использует `os.walk()` для рекурсивного обхода каждой директории.
    3.  Пропускает системные папки (например, скрытые папки, начинающиеся с `.`, или `~$` временные файлы Word).
    4.  Проверяет имя файла через `fnmatch.fnmatch(filename.lower(), mask.lower())`.
    5.  Возвращает генератор (yield) найденных путей, чтобы не загружать память сразу списком из 100 000 файлов.
*   **Результат:** Для каждого найденного файла мы сразу проверяем его в БД (из Этапа 1.2). Если его нет — добавляем со статусом `FOUND` (Найден). Если есть — статус `EXISTS` (Уже в базе).

### 🧵 3.2. Многопоточность, Фоновый режим и Остановка (Threading & Cancellation)

**Цель:** Реализовать неблокирующий поиск и возможность его прервать.

**Технические детали (`core/search/manager.py`):**
*   **Класс `SearchManager` (Singleton):**
    *   Хранит в себе ссылку на текущий поток: `self.thread = None`.
    *   Хранит флаг отмены: `self.stop_event = threading.Event()`.
    *   Хранит текущий прогресс: `self.processed_files = 0`, `self.total_found = 0`.
*   **Запуск поиска (`start_search`):**
    *   Если поток уже запущен — ничего не делает (защита от дурака).
    *   Очищает `stop_event` (устанавливает в `False`).
    *   Запускает `threading.Thread(target=self._search_worker, daemon=True)`.
*   **Рабочий цикл (`_search_worker`):**
    *   Вызывает `scanner.py` для обхода папок.
    *   **Критически важно:** После каждого найденного файла проверяет `self.stop_event.is_set()`. Если `True` — прерывает цикл и завершает поток.
    *   Обновляет прогресс (для UI).
*   **Остановка поиска (`stop_search`):**
    *   Устанавливает `self.stop_event.set()`. Поток завершится сам на следующей итерации.

### 📊 3.3. Управление статусами и Очередь обработки

**Цель:** Четко отслеживать жизненный цикл файла в приложении.

**Технические детали (`core/database.py`):**
*   **Обновление статусов:** В таблице `files` колонка `status` теперь принимает строго определенные значения (Enum):
    *   `FOUND` — Найден на диске (только что добавлен).
    *   `EXISTS` — Уже был в базе (дубликат по пути).
    *   `QUEUED` — Пользователь выбрал его (чекбокс) и нажал «Сохранить», файл ждет парсинга.
    *   `PROCESSING` — В данный момент читается и парсится.
    *   `PARSED` — Успешно обработан, CSV создан.
    *   `ERROR` — Ошибка парсинга (сюда же пишем текст ошибки).
*   **Очередь задач (`TaskManager`):**
    *   Когда пользователь нажимает «Сохранить», мы не должны парсить 100 файлов в главном потоке (интерфейс зависнет).
    *   Создается второй рабочий поток (`worker`), который берет выбранные файлы по одному, меняет статус на `PROCESSING`, вызывает парсер (Этап 1), маппер (Этап 2), сохраняет CSV и ставит статус `PARSED`.
    *   Если в процессе ошибка — статус `ERROR` + текст ошибки в БД, поток идет к следующему.

### 🔌 3.4. API-слой для взаимодействия с будущим GUI

**Цель:** Подготовить функции, которые мы повесим на кнопки интерфейса (PyWebView/JS).

**Технические детали (`api/controller.py`):**
*   `api_start_search(directories, mask, background_mode)` — возвращает `{"status": "started"}`. Если `background_mode=False`, функция блокируется до конца поиска (или делает это через asyncio, если выберем FastAPI).
*   `api_stop_search()` — вызывает `SearchManager.stop_search()`.
*   `api_get_status()` — возвращает JSON текущего состояния (идет ли поиск, сколько файлов обработано, скорость).
*   `api_get_files()` — возвращает список файлов из БД (для отрисовки таблицы в HTML) с их статусами и путями.
*   `api_process_selected(file_ids: list)` — запускает фоновый парсинг выбранных файлов.
