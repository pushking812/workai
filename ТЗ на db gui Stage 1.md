# 📋 Детальная проработка Этапа 1: Ядро, База данных и Базовый Парсинг

**Цель этапа:** Создать фундамент приложения. Мы не работаем с GUI. Весь код пишется так, чтобы его можно было протестировать через консольные скрипты или юнит-тесты. На выходе этапа мы должны получить инструмент, который берет папку с DOCX-файлами, считает их хэши, извлекает таблицы, очищает текст и складывает результат в CSV и базу данных SQLite.

### 📁 1.1. Инициализация проекта и База данных (SQLite)

**Цель:** Настроить структуру проекта и создать базу для хранения информации о файлах.

**Технические детали:**
*   **Структура папок:**
    ```text
    project_root/
    ├── core/               # Бизнес-логика
    │   ├── __init__.py
    │   ├── database.py     # Работа с SQLite
    │   ├── hasher.py       # Хеширование
    │   └── parsers/        # Парсеры
    │       ├── __init__.py
    │       └── docx_parser.py
    ├── data/               # Данные (добавить в .gitignore)
    │   ├── app.db
    │   └── exports/        # Сюда будут складываться CSV
    ├── tests/              # Тесты
    └── main.py             # Временная точка входа для тестов
    ```
*   **Схема БД (таблица `files`):**
    *   `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
    *   `hash` (TEXT NOT NULL) — SHA-256 хэш файла
    *   `path` (TEXT NOT NULL) — Полный путь к файлу
    *   `filename` (TEXT NOT NULL) — Имя файла
    *   `status` (TEXT NOT NULL DEFAULT 'SAVED') — Статус из единого Enum: SAVED (hash, путь, CSV и нормализованные заголовки записаны), PROCESSING (идёт обработка), NEEDS_MAPPING (есть схема без полного маппинга), READY (заголовки сопоставлены, файл можно передавать в Excel), ERROR (текст в error_message). Статусы FOUND и «уже в базе» существуют только в UI и в БД не хранятся.
    *   `error_message` (TEXT) — Текст ошибки (для статуса ERROR)
    *   `doc_code` (TEXT) — Полный шифр документа из штампа (например, `ЕСТ-ПМ-80825-Р-1-ИСВН.ВОР`). Главный идентификатор документа; `path` на уникальность не влияет.
    *   `project_code` (TEXT) — Шифр проекта (`ЕСТ-ПМ-80825-Р`)
    *   `section_code` (TEXT) — Раздел проекта (`ИСВН`, `ЭС1`)
    *   `doc_type` (TEXT) — Тип документа (`ВОР`, `СО`); пусто, если в штампе тип не указан (чертёж)
    *   `revision` (TEXT NOT NULL DEFAULT '0') — Номер изменения из штампа; `0` — изменения нет
    *   `revision_date` (TEXT) — Дата выпуска изменения: из штампа для официальных, из имени файла для неофициальных. Хранится как `ISO` (`YYYY-MM-DD`), сырое значение — в `stamp_raw`
    *   `sheet` (INTEGER) — Номер листа из штампа
    *   `sheets_total` (INTEGER) — Количество листов из штампа
    *   `stamp_raw` (TEXT) — JSON сырых ячеек штампа (для аудита и отладки парсера)
    *   `stamp_status` (TEXT NOT NULL DEFAULT 'OK') — `OK` / `PARTIAL` (штамп распознан не полностью) / `MISSING` (штампа нет)
    *   `variant_group` (TEXT) — Хэш от `(doc_code, revision, revision_date)`; объединяет варианты документа, различающиеся только содержимым при одинаковых реквизитах штампа
    *   `is_current` (INTEGER NOT NULL DEFAULT 1) — 1 для текущей версии документа (`doc_code`), 0 для истории. Текущая версия — запись с максимальным `revision` и самой поздней `revision_date` внутри `doc_code`. Если у нескольких записей реквизиты полностью совпадают, но различается хэш, они обе остаются `is_current = 1` как варианты до решения пользователя. В «Подготовить» участвуют только записи с `is_current = 1`.
    *   `csv_path` (TEXT) — Путь к сгенерированному CSV
    *   `created_at` (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
    *   *Ограничение:* `UNIQUE(hash, path)` — защита от повторного добавления физически того же файла по тому же пути. Уникальность документа и определение версии через путь **не выполняется**: этим занимаются `doc_code`/`revision`/`revision_date`/`variant_group`.

**Ключевые функции (`core/database.py`):**
*   `init_db()` — создание таблиц, если их нет.
*   `add_file(hash, path, filename, stamp)` — добавление записи вместе с реквизитами штампа.
*   `get_current_by_path(path)` — текущая запись по пути (для проверки неизменности файла).
*   `get_by_variant_group(variant_group)` — все варианты документа с одинаковыми реквизитами штампа.
*   `update_file_status(file_id, status, csv_path=None)` — обновление статуса после парсинга.
*   `recalc_is_current(doc_code)` — пересчёт актуальности версий внутри документа.

**Критерии готовности:** Скрипт создает файл `app.db`, в нем есть таблица `files`, функции добавления и чтения работают.

### 🔐 1.2. Модуль хеширования и проверки файлов

**Цель:** Научиться безопасно (без перегрузки памяти) читать файлы и проверять их на дубликаты.

**Технические детали (`core/hasher.py`):**
*   **Алгоритм:** SHA-256. Чтение файла блоками по 8192 байта (чтобы не загружать гигабайтные файлы в память).
*   **Логика проверки (Дубликаты и версии):** документ определяется штампом, а не путём:
    1. Вычисляем хэш файла и разбираем штамп (шифр, изм., дата, лист/листов).
    2. `doc_code` — идентификатор документа, `revision` + `revision_date` — версия. Документ без изма в штампе имеет `revision = '0'`.
    3. Ищем в БД записи с этим `doc_code` и `revision` и `revision_date` (т.е. тот же `variant_group`).
    4. *Если таких записей нет* — добавляем новую версию: `is_current = 1`, у прежних версий этого `doc_code` `is_current` становится 0.
    5. *Если записи есть и одна из них имеет тот же `hash`* — это тот же документ, ничего не меняем (возвращаем `ALREADY_EXISTS`).
    6. *Если записи есть, но `hash` отличается* — это ещё один вариант документа при тех же реквизитах штампа. Добавляем новую запись с тем же `variant_group` и `is_current = 1`. Решение, какой вариант оставить, принимает пользователь; на этот случай обе записи остаются текущими, а UI показывает их рядом со всей информацией (путь, размер, дата файла, хэш, дата изменения из штампа).
    7. `path` на уникальность и версию не влияет — это только дополнительные данные для решения пользователя.

**Ключевые функции:**
*   `calculate_sha256(file_path) -> str`
*   `compute_variant_group(doc_code, revision, revision_date) -> str`
*   `process_file_entry(file_path) -> dict` — возвращает словарь `{"result": "NEW/ALREADY_EXISTS/NEW_VERSION/NEW_VARIANT", "hash": "...", "path": "...", "doc_code": "...", "revision": "...", "revision_date": "...", "variant_group": "...", "is_current": 1}`.

**Критерии готовности:** Запускаем скрипт на папке. Файлы без дублей добавляются в БД. Если скопировать файл в другую папку и запустить снова — создается вторая запись (дубликат). Если запустить дважды на одной папке — ничего не меняется.

### 📄 1.3. Парсер DOCX (Ядро)

**Цель:** Извлечь таблицы из документов, корректно обработать объединенные ячейки, собрать шапку (многострочные и групповые заголовки) и сохранить в CSV.

**Технические детали (`core/parsers/docx_parser.py`):**
*   **Библиотека:** `docx2python`.
*   **Извлечение:** Метод `docx2python(file_path).body` возвращает вложенные списки: `[Таблица][Строка][Ячейка]`.
*   **Очистка текста (Критически важно):** Внутри ячейки `docx2python` может вернуть список строк (если там несколько абзацев) или строку с переносами `\n`.
    *   *Функция очистки:* Рекурсивно проходит по ячейке, склеивает все куски в одну строку, заменяет `\n`, `\r`, `\t` на пробелы, удаляет лишние пробелы по краям (`strip()`).
*   **Многострочные и групповые заголовки:** шапка ВОР бывает сложной, её нельзя брать одной строкой `table[0]`:
    *   Заголовок может занимать несколько строк внутри одной ячейки (`['№', 'п/п']`, `['Ед.', 'изм.']`) — после `clean_cell_text` такие строки склеиваются в `"№ п/п"`, `"Ед. изм."`.
    *   Следующая строка шапки может быть строкой нумерации колонок (`1, 2, 3, ...`) — она отбрасывается и в CSV не пишется.
    *   Строка-группа (объединённая ячейка с названием раздела, например `Оборудование`) не является заголовком колонки: её текст запоминается и добавляется как префикс к подзаголовкам, которые идут ниже и относятся к этой группе (`Оборудование` + подзаголовок).
    *   Заголовок-родитель с вложенными подзаголовками (объединение по горизонтали) раскрывается как `РодительПодзаголовок`.
    *   Итог функции `extract_headers(table)`: один список заголовков длиной в число колонок, плюс индекс первой строки данных.
    *   Функция `is_numbering_row(row, width) -> bool` — определяет строку нумерации колонок.
*   **Экспорт в CSV:**
    *   Для каждой извлеченной таблицы создается отдельный CSV файл; в нём пишется одна строка заголовков (собранная по правилам выше) и затем строки данных.
    *   *Путь:* `data/exports/{hash}_table_1.csv` (чтобы не было конфликтов имен). Пути всех CSV одного файла собираются и записываются в `files.csv_path` через `;`.
    *   *Кодировка:* `utf-8-sig` (чтобы Excel открывал кириллицу без кракозябр).
*   **Интеграция с БД:** После успешного сохранения CSV в БД записываются пути ко всем CSV файла (через `;` в `csv_path`), а статус файла становится `SAVED`. Заголовки на этом шаге не обрабатываются: их нормализация происходит позже, по кнопке «Подготовить».

**Ключевые функции:**
*   `clean_cell_text(cell) -> str` — очистка текста в ячейке.
*   `extract_tables_from_docx(file_path) -> list` — возвращает список таблиц (список списков строк ячеек).
*   `extract_headers(table) -> tuple[list[str], int]` — собранная шапка и индекс первой строки данных.
*   `save_table_to_csv(table_data, output_path, headers=None)` — сохраняет таблицу в CSV.

**Критерии готовности:** Запускаем на проблемном Word-файле (том, где были объединенные ячейки). Открываем полученный CSV в Excel: все колонки на своих местах, объединенные ячейки заполнены правильным текстом (без сдвигов влево), текст очищен от случайных переносов строк.

### 🧾 1.4. Парсер штампа документа (Метаданные из колонтитула)

**Цель:** Автоматически получать реквизиты документа из таблицы штампа в нижнем колонтитуле — это главный идентификатор документа и его версии, без него невозможно определить, что перед нами: новый документ, новая версия или второй вариант.

**Технические детали (`core/parsers/stamp_parser.py`):**
*   **Источник:** `docx2python(file_path).footer` — список секций, в каждой список таблиц. Штамп находится не в первой таблице, поэтому таблицы просматриваются все, а нужная определяется по содержимому (наличие шифра документа).
*   **Разбор шифра:** шифр вида `ЕСТ-ПМ-80825-Р-1-ИСВН.ВОР` разбирается как:
    *   `project_code` — часть до последнего `-N`, где `N` — цифра номера комплекта (`ЕСТ-ПМ-80825-Р`);
    *   `section_code` — часть после номера комплекта до точки (`ИСВН`, `ЭС1`);
    *   `doc_type` — часть после точки (`ВОР`, `СО`). Если точка и тип отсутствуют (`ЕСТ-ПМ-80825-Р-1-ИСВН`) — `doc_type` пустой, документ считается чертежом.
    *   `doc_code` — шифр целиком, нормализованный (верхний регистр, без пробелов).
*   **Реквизиты из штампа:** `revision` (колонка `Изм.`), `revision_date` (колонка `Дата`), `sheet` (`Лист`), `sheets_total` (`Листов`). Отсутствие `Изм.` — `revision = '0'`.
*   **Дата:** из штампа для официальных документов; если в штампе даты нет — дата из имени файла (неофициальный выпуск). Обе приводятся к `ISO` (`YYYY-MM-DD`), двухзначный год трактуется как `20XX`.
*   **Устойчивость:** шифр в штампе повторяется в нескольких таблицах и колонках — берутся уникальные значения; если распознано несколько разных шифров, выбирается наиболее часто встречающийся, а в `stamp_raw` сохраняется всё.
*   **Результат:** словарь метаданных и `stamp_status`: `OK`, `PARTIAL` (штамп найден, но часть полей не распознана) или `MISSING` (штампа нет). Файл без штампа всё равно сохраняется в базу, но помечается `stamp_status = 'MISSING'` и требует внимания пользователя.

**Ключевые функции:**
*   `parse_stamp(file_path) -> dict` — шифр, проект, раздел, тип, изм., дата, лист, листов, `stamp_raw`, `stamp_status`.
*   `parse_doc_code(doc_code) -> dict` — разбор шифра на `project_code` / `section_code` / `doc_type`.
*   `parse_revision_date(text) -> str | None` — нормализация даты в `ISO`.
*   `parse_date_from_filename(filename) -> str | None` — дата для неофициальных выпусков.

**Критерии готовности:**
*   `16_ЕСТ-ПМ-80825-Р-1-ЭС1_ВОР.docx` → `doc_code = ЕСТ-ПМ-80825-Р-1-ЭС1.ВОР`, `project_code = ЕСТ-ПМ-80825-Р`, `section_code = ЭС1`, `doc_type = ВОР`, `revision = 1`, `revision_date = 2025-08-01`, `sheet = 1`, `sheets_total = 5`.
*   `ЕСТ-ПМ-80825-Р-1-ИСВН_ВОР.docx` → `doc_code = ЕСТ-ПМ-80825-Р-1-ИСВН.ВОР`, `revision = 0`, `revision_date = 2026-02-06`.
