# 📋 Детальная проработка Этапа 4: Каркас GUI и Главное окно (Frontend Base)

**Цель этапа:** Оживить приложение. Мы создадим нативное окно, отрисуем в нем главный экран (кнопки, таблицу со списком файлов) и научим интерфейс общаться с нашим Python-бэкендом (вызывать поиск, получать статусы, обновлять таблицу).

На этом этапе мы используем **PyWebView** (связка Python + HTML/CSS/JS).

---

### 🪟 4.1. Инициализация PyWebView и Мост (API Bridge)

**Цель:** Запустить окно приложения и пробросить Python-функции в JavaScript.

**Технические детали (`main.py` и `api/webview_api.py`):**
1.  **Создание класса API:**
    *   Создаем класс `Api`, методы которого будут вызываться из JS.
    *   *Пример методов:* `start_search()`, `stop_search()`, `get_status()`, `get_files()`, `add_files_dialog()`.
2.  **Настройка окна:**
    *   `webview.create_window(title="БД Строительных Документов", url="ui/index.html", js_api=Api())`.
    *   Настройка размеров окна по умолчанию (например, 1200x800), включение возможности изменения размера.
3.  **Механика общения (Polling):**
    *   Так как PyWebView не имеет встроенных WebSockets «из коробки», для обновления прогресса поиска (когда бэкенд работает в фоне) используем **опрос (Polling)**.
    *   JS будет вызывать `window.pywebview.api.get_status()` каждые 500-1000 мс, пока идет поиск.

---

### 🎨 4.2. Верстка главного окна (HTML/CSS/JS)

**Цель:** Создать удобный и отзывчивый интерфейс.

**Технические детали (`ui/index.html`, `ui/css/style.css`):**
1.  **Шапка (Header):**
    *   Логотип/Название приложения.
    *   Группа кнопок: `Настройки`, `Поиск`, `Остановить поиск`, `Добавить файл`, `Сохранить`.
    *   Индикатор статуса: текст «Готово», «Идет поиск...», «Обработка...».
2.  **Панель инструментов (Toolbar):**
    *   Чекбокс «Фоновый режим».
    *   Поле поиска/фильтра по уже найденным файлам в таблице (чтобы быстро найти нужный ВОР в списке).
    *   Кнопка «Выделить все» / «Снять выделение».
3.  **Таблица файлов (DataGrid):**
    *   Используем обычный HTML `<table>` или легковесную JS-библиотеку (например, **Tabulator** или **Grid.js** — они дают сортировку, фильтрацию и красивый вид из коробки).
    *   *Колонки:* `[Чекбокс] | Имя файла | Путь | Статус (цветной бейдж) | Размер | Дата изменения`.
    *   *Цветовая индикация статусов (CSS):*
        *   `FOUND` (Найден) — синий/серый.
        *   `QUEUED` (В очереди) — желтый.
        *   `PROCESSING` (Обработка) — оранжевый (с анимацией спиннера).
        *   `PARSED` (Готово) — зеленый.
        *   `ERROR` (Ошибка) — красный (при клике показывает текст ошибки).

### 🔄 4.3. Связывание UI с Бэкендом (Frontend Logic)

**Цель:** Научить JavaScript вызывать методы Python и обновлять интерфейс.

**Технические детали (`ui/js/app.js`):**
1.  **Загрузка данных при старте:**
    *   При `window.onload` вызываем `window.pywebview.api.get_files()`.
    *   Получаем JSON с файлами из БД и отрисовываем таблицу.
2.  **Обработка кнопки «Поиск»:**
    *   Считываем настройки (директории) из бэкенда (или из модального окна, если оно открыто).
    *   Вызываем `window.pywebview.api.start_search()`.
    *   Блокируем кнопку «Поиск», активируем «Остановить».
    *   Запускаем `setInterval` для опроса `get_status()`, обновляем прогресс-бар и таблицу (если бэкенд возвращает новые файлы).
3.  **Обработка кнопки «Остановить»:**
    *   Вызываем `window.pywebview.api.stop_search()`.
    *   Останавливаем `setInterval`. Меняем статус на «Остановлено пользователем».
4.  **Кнопка «Добавить файл» (Диалог ОС):**
    *   Вызываем метод API `add_files_dialog()`.
    *   В Python используем `webview.windows[0].create_file_dialog(webview.OPEN_DIALOG, allow_multiple=True, file_types=('Word Documents (*.docx)',))`.
    *   Полученные пути возвращаем в JS и добавляем в таблицу (через метод `api.process_manual_add(paths)`).
5.  **Управление чекбоксами:**
    *   JS хранит массив `selected_file_ids`.
    *   При клике на чекбокс обновляем этот массив.
    *   Кнопка «Сохранить» (или «Обработать») активна только если массив не пуст.
