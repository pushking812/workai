# 📋 Детальная проработка Этапа 5: Интерактивные окна (Модальные окна GUI)

**Цель этапа:** Реализовать пользовательский интерфейс для настройки приложения и, самое главное, создать **Окно сопоставления колонок (Mapping Modal)**. Это окно станет «мозгом» интерфейса, позволяя пользователю вручную исправлять ошибки парсинга и обучать систему.

На этом этапе мы соединяем логику бэкенда (Этап 2) с визуальной оболочкой (Этап 4).

---

### ⚙️ 5.1. Окно настроек (Settings Modal)

**Цель:** Дать пользователю возможность управлять параметрами поиска и экспорта без редактирования файлов конфигурации.

**Технические детали:**
*   **UI (HTML/CSS/JS):**
    *   Модальное окно, перекрывающее фон.
    *   **Поле «Префикс»:** Текстовый input (для парсинга ссылок на чертежи, например, `ЕСТ-ПМ-80825-Р-`).
    *   **Директории поиска:** Список (теги или textarea), куда пользователь добавляет пути. Можно добавить кнопку «Выбрать папку» (вызывает системный диалог через PyWebView).
    *   **Фоновый поиск:** Чекбокс (Вкл/Выкл).
    *   **Контроль актуальности файлов:** Чекбокс (проверять хэш при обновлении).
    *   Кнопки `Сохранить` и `Отмена`.
*   **Бэкенд (Python):**
    *   Создание файла `config.json` в корне проекта (или таблица `settings` в БД).
    *   `api.get_settings()` — возвращает текущие настройки в JSON.
    *   `api.save_settings(settings_dict)` — валидирует (проверяет, что папки существуют) и сохраняет настройки.

### 📂 5.2. Окно выбора файлов (File Dialog)

**Цель:** Реализовать вызов системного диалога для ручного добавления документов, минуя поиск по папкам.

**Технические детали:**
*   **Бэкенд (Python):**
    *   Вызов `webview.windows[0].create_file_dialog(webview.OPEN_DIALOG, allow_multiple=True, file_types=('Word Documents (*.docx)',))`.
    *   Полученные пути прогоняются через логику Этапа 1.2 (штамп → шифр/изм./дата → определение версии) и добавляются в БД со статусом `SAVED`, если такого документа с такой версией ещё нет или файл отличается содержимым (тогда он становится вариантом); в UI до сохранения запись отображается как `FOUND`.
*   **UI (JS):**
    *   При нажатии кнопки «Добавить файл» вызывается API.
    *   После получения ответа таблица обновляется (новые строки добавляются в грид).

### 🧩 5.3. Окно сопоставления колонок (Mapping Modal) — Ключевая фича

**Цель:** Визуализировать «Схемы» (из Этапа 2), которые не удалось автоматически сопоставить со справочником, и дать пользователю возможность связать их с каноническими именами.

**Логика работы:**
1. При попытке сохранить файлы (или нажать «Подготовить») бэкенд проверяет: есть ли среди выбранных файлов те, у которых `mapping_json` пустой или неполный.
2. Если такие есть — вызывается это модальное окно.
3. Пользователь видит **группы** (схемы). Одно и то же сопоставление применяется сразу ко всей группе (например, 15 файлов с одинаковым набором кривых колонок).

**Технические детали UI:**
*   **Левая панель (Список схем):**
    *   Сгруппированные по `schema_hash` уникальные наборы заголовков.
    *   Показывает, сколько файлов относится к этой схеме (например, «Схема 1 (12 файлов)»).
    *   Показывает исходные заголовки (например: `["№", "Работа", "Ед", "Объем", "Ссылка"]`).
*   **Правая панель (Сопоставление):**
    *   Отображается при клике на схему слева.
    *   Это таблица из двух колонок: **«Заголовок из Word»** и **«Каноническое имя»**.
    *   Для каждой строки в колонке «Каноническое имя» находится выпадающий список (`<select>`).
    *   *Важно:* Мы заранее подставляем туда автоматический выбор (из `fuzzy_matcher`), если уверенность > 85%.
    *   *Игнорирование колонок:* В выпадающем списке есть пункт `--- Игнорировать ---` (если в Word есть мусорный столбец, который не нужен в БД).
    *   *Отсутствующие колонки:* Внизу списка выводятся канонические колонки, которых нет в Word (с пометкой «Добавить как NULL»). Пользователь может их включить.
*   **Сортировка (Drag-and-Drop):**
    *   Используем библиотеку **SortableJS**.
    *   Пользователь может перетаскивать строки в правой панели, чтобы задать итоговый порядок колонок в базе (например, чтобы `NПП` всегда был первым, даже если в Word он был третьим).
*   **Кнопки:** `Применить к выбранной схеме` и `Применить ко всем схемам`.

### 🔄 5.4. Сохранение правил и обновление БД

**Цель:** Обучить систему, чтобы в следующий раз она не спрашивала пользователя о тех же заголовках.

**Технические детали (`core/database.py` и `core/transformer`):**
1.  **Сохранение синонимов:** Когда пользователь связал `"Объем"` -> `"КолВо"`, мы берем нормализованное `"объем"` и записываем в таблицу `header_synonyms` (с высоким `confidence_score` = 1.0).
2.  **Сохранение маппинга схемы:** В таблицу `schemas` записывается итоговый JSON-словарь сопоставления. Теперь эта схема считается «Обученной».
3.  **Перезапуск парсинга:** Для файлов, которые ждали маппинга, автоматически запускается процесс применения маппинга (из Этапа 2.4), генерации CSV и обновления статуса в БД на `READY` (если маппинг покрывает все нужные колонки) или `NEEDS_MAPPING` (если остались несопоставленные).

### 📦 План коммитов для Этапа 5

1.  **`feat(api): create settings module (load/save json)`**
    *   Написание функций чтения/записи `config.json`. Создание API-методов `get_settings` и `save_settings`.
2.  **`feat(ui): create settings modal and connect to api`**
    *   Верстка формы настроек. Привязка кнопки «Сохранить» к API. Заполнение полей при открытии.
3.  **`feat(api): add native file dialog handler`**
    *   Реализация метода `add_files_dialog` через `webview.create_file_dialog`.
4.  **`feat(ui): create mapping modal skeleton`**
    *   Верстка двухпанельного окна. Левая панель со списком схем (пока на тестовых данных). Правая панель с выпадающими списками.
5.  **`feat(api): implement get_unmapped_schemas endpoint`**
    *   Метод бэкенда, который достает из БД схемы без маппинга, прогоняет их через `rapidfuzz` и возвращает JSON для отрисовки.
6.  **`feat(ui): render mapping dropdowns and suggestions`**
    *   JS-логика: динамическое создание `<select>` для каждой колонки. Установка выбранного значения по умолчанию (из подсказки fuzzy-матчера).
7.  **`feat(ui): integrate SortableJS for column ordering`**
    *   Подключение библиотеки, инициализация `new Sortable()` для возможности перетаскивания строк.
8.  **`feat(api): implement save_mapping_and_process`**
    *   Бэкенд-метод, принимающий JSON маппинга, сохраняющий его в БД (`header_synonyms` и `schemas`) и запускающий фоновую обработку выбранных файлов.
9.  **`test: simulate full mapping flow`**
    *   Интеграционный тест: загрузка файла с кривыми заголовками -> открытие окна маппинга -> сохранение правил -> проверка, что в БД появился синоним и CSV сгенерировался.
